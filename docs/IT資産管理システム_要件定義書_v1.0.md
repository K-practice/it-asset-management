## 1. 背景・目的

### 1.1 開発背景

開発者は4年制IT系専門学校の2年生で、翌年から始まる就職活動に向けてポートフォリオを制作する。クラウドエンジニアを志望しており、将来的にAWS・Docker・Terraformなどを追加できる作品とする。

本作品は複数のポートフォリオのうちの1つとして位置付け、初期版は比較的低い難易度で完成できる範囲にする。「難易度と就活評価のバランス」を最重視する。

### 1.2 解決する課題【確定】

小規模企業において、PCやネットワーク機器の所在・利用者が分からない問題を解決する。

### 1.3 システムの目的【確定】

社内の機器について「どこにあるか」「誰が使っているか」「どのような状態か」を確認できるようにする。

### 1.4 完成時に説明できる内容【提案】

- 課題に沿った要件定義と、初期版・将来拡張の範囲分け。
- FlaskとMariaDBによるデータの登録・参照・更新・論理削除。
- 管理担当者と一般利用者の権限分離。
- 場所・利用者・状態・種別・管理番号の変更履歴。
- 検索・絞り込み・CSV出力による管理業務の支援。
- セキュリティ対策、検証結果、セットアップ手順。

就職活動での評価を保証するものではなく、成果物で示す内容の整理とする。

## 3. 利用対象・権限

### 3.1 想定組織【確定】

小規模な企業の社内。管理対象は以下に限定する。

- PC：ノートPC・デスクトップPC。
- ネットワーク機器：ルーター・スイッチなど。

周辺機器は初期版の管理対象に含めない。

### 3.2 利用者【確定】

| 利用者 | 主な役割 |
|---|---|
| 管理担当者 | 機器の登録・更新、管理業務、履歴確認 |
| 一般利用者 | 社内のすべての機器について、現在の情報を閲覧 |

個人への機器の割り当ては、ログインアカウントを持つ社員に限る。アカウントは管理担当者が作成する。

### 3.3 権限表【確定事項と必要な動作の整理】

| 操作 | 管理担当者 | 一般利用者 |
|---|---|---|
| ログイン・ログアウト | 可 | 可 |
| 自分のパスワード変更 | 可 | 可 |
| 社内の機器一覧・詳細の閲覧 | 可 | 可 |
| キーワード検索・条件絞り込み | 可 | 可 |
| 機器の登録・更新 | 可 | 不可 |
| 機器の論理削除・復元 | 可 | 不可 |
| 削除済み機器の確認 | 可 | 不可 |
| 場所・利用者・状態・種別・管理番号の変更履歴の閲覧 | 可 | 不可 |
| 検索結果のCSV出力 | 可 | 不可 |
| 場所の管理 | 可 | 不可 |
| アカウントの作成・氏名編集・無効化・再有効化 | 可 | 不可 |
| 他者のパスワードリセット | 可 | 不可 |

未ログインの利用者には機器情報や管理機能を公開しない【整理】。ボタンの非表示に加え、サーバー側で各操作の権限を確認する【整理】。

## 4. 機器の管理方針

### 4.1 管理番号【確定】

機器の管理番号を自動採番する。DB内部の識別IDと、画面・現物の照合に使う管理番号は目的を区別する。

管理番号はPC-000001・NET-000001の形式で、種別ごとに独立した連番を自動採番する【確定】。登録後の種別変更を許可し、変更先の種別の管理番号を再発行する【確定】。DB内部の機器IDと既存履歴は保持する【整理】。管理番号そのものの手入力・直接編集は行わない【整理】。

管理番号は重複させない【整理】。確定済み番号を再利用しないこと、6桁を超えた番号の表示方法はDB設計書の初期案として管理する。

### 4.2 場所【確定】

- 部屋・エリア単位で管理する。
- 管理担当者が場所を事前登録し、機器の登録・更新時に選択する。
- 場所の名称変更・利用停止・利用再開を管理する。
- 機器が残っている場所も利用停止できる。既存の所在を保持し、新規選択を禁止する。
- 利用停止した場所を含め、場所名の重複を禁止する。
- 編集・復元時に、既存の停止場所を変更せず保持できる。
- 座席・棚などの詳細は、任意の「所在補足」に入力できる。
- 拠点別の階層管理や、座席・棚の専用管理は初期版に含めない。

### 4.3 利用者【確定】

| 区分 | 意味 | 割当先の社員 |
|---|---|---|
| 個人利用 | 特定の社員1人に割り当てる | 1人 |
| 共有 | 複数人で使う機器 | 指定しない |
| 未割当 | 利用者が決まっていない機器 | 指定しない |

1台に複数の社員を登録する方式は採用しない。共有区分は個々の利用者を列挙する機能ではない。

個人利用には割当先が必要で、共有・未割当には割当先を設定しない【整理】。無効なアカウントへの新規割当は禁止する【確定】。

### 4.4 機器の状態【確定】

| 状態 | 意味 |
|---|---|
| 使用中 | 利用中の機器 |
| 保管中 | 予備などとして保管している機器 |
| 故障 | 故障により通常の利用ができない機器 |
| 廃棄 | 廃棄済みの機器 |

「修理中」は設けず、修理中の機器は「故障」として扱う。「共有・未割当」は利用者区分であり、状態とは別に管理する。

使用中は「個人利用」または「共有」、廃棄は「未割当」とする【確定】。保管中・故障は3区分とも許可する【整理】。整合しない入力では保存を拒否し、利用者区分・割当先の修正を求める【整理】。状態変更だけで割当を自動解除しない。廃棄から他の状態への訂正を許可し、状態・割当の整合ルールと履歴保存を適用する【確定・整理】。

### 4.5 論理削除・復元【確定・整理】

- 重複・誤登録の機器は論理削除する。
- 論理削除してもデータと既存の変更履歴を保持する。
- 管理担当者が削除済み機器を確認し、復元できる。
- 通常一覧・通常検索・CSV出力から削除済み機器を除外する。
- 一般利用者は削除済み機器を、URLを直接指定しても閲覧できない。
- 廃棄した実在の機器は削除せず、状態を「廃棄」にして記録を残す。

論理削除と廃棄は別の操作として扱う。削除・復元自体の操作ログは、今回選択された「場所・利用者・状態・種別・管理番号の変更履歴」とは別であり、追加の確定機能とはしない。

## 5. 管理する情報

以下は画面上の論理項目であり、DBのテーブル名・カラム名・型・文字数は詳細設計で定義する。

### 5.1 機器情報【確定事項の整理】

| 項目 | 入力・取得方法 | 必須・任意 |
|---|---|---|
| 管理番号 | 自動採番 | 自動設定 |
| 機器名 | 入力 | 必須 |
| 種別 | PC／ネットワーク機器から選択 | 必須 |
| 場所 | 登録済みの場所から選択 | 必須 |
| 所在補足 | 自由入力 | 任意 |
| 利用者区分 | 個人利用／共有／未割当から選択 | 必須 |
| 割当先の社員 | アカウントから選択 | 個人利用の場合に必須 |
| 状態 | 使用中／保管中／故障／廃棄から選択 | 必須 |
| メーカー | 入力 | 任意 |
| 型番 | 入力 | 任意 |
| シリアル番号 | 入力。重複を許可 | 任意 |
| 備考 | 自由入力 | 任意 |
| 登録日時 | 自動記録 | 自動設定 |
| 更新日時 | 自動記録 | 自動設定 |

管理番号はシステムが付与する番号、シリアル番号はメーカーが付与する製造番号として区別する。

購入日・購入金額・購入先、CPU・メモリなどの仕様情報は初期版に含めない。機器のログインパスワードや秘密鍵は管理対象にしない【既提示の設計方針】。

### 5.2 アカウント情報【必要情報の整理・詳細は提案】

- 社員を識別するID、氏名。
- ログイン用識別子とパスワードのハッシュ値。
- 権限：管理担当者／一般利用者。
- 有効／無効。
- 初回・リセット後のパスワード変更が必要かを示す情報。

専用のログインIDを使用し、大文字・小文字を区別しない【確定】。半角英数字と . _ - のみを許可し、空白・全角文字・日本語は禁止する【確定】。社員番号・部署は初期版の確定項目に含めない。

### 5.3 場所情報【必要情報の整理】

場所を識別するID、場所名、利用中／利用停止を管理する。停止した場所を含めて場所名の重複を禁止し、機器が残っていても停止・再開できる【確定】。場所名は前後の空白を除去して保存・比較し、英字の大小文字は区別する【確定】。

### 5.4 変更履歴【確定】

機器の場所・利用者・状態・種別・管理番号が変更された際、次を保存する。

- 対象機器。
- 変更日時。
- 変更者。
- 変更項目。
- 変更前の内容。
- 変更後の内容。

場所名・社員名は変更当時の名称を保存して表示する【確定】。現在の名称への変更で過去の表示を書き換えない。

利用者の変更には、区分の変更と割当先の変更を含む【整理】。メーカー・型番・備考など、その他の項目の変更履歴は初期版では保存しない。

## 6. 機能要件

すべて初期版の対象。IDは設計・実装・検証時の対応付けに使用する。

| ID | 機能 | 要求内容 |
|---|---|---|
| F-01 | 認証 | 有効なアカウントでログイン・ログアウトできる |
| F-02 | パスワード変更 | 本人が変更でき、初回・リセット後は変更を必須にする |
| F-03 | アカウント管理 | 管理担当者が作成・氏名編集・無効化・再有効化・パスワードリセットを行える。最後の有効な管理担当者の無効化は禁止 |
| F-04 | 場所管理 | 管理担当者が場所を登録・名称変更・利用停止・利用再開できる |
| F-05 | 機器登録 | 管理担当者が必要な情報を登録し、管理番号を自動採番する |
| F-06 | 機器一覧 | 管理担当者・一般利用者が社内の現在の機器情報を一覧で確認できる |
| F-07 | 機器詳細 | 管理担当者・一般利用者が機器の現在の情報を確認できる |
| F-08 | 機器更新 | 管理担当者が場所・利用者・状態・種別・任意項目などを更新できる。種別変更時は管理番号を再発行 |
| F-09 | 履歴保存・閲覧 | 場所・利用者・状態・種別・管理番号の変更履歴を保存し、管理担当者が閲覧できる |
| F-10 | 論理削除・復元 | 管理担当者が機器を通常表示から除外し、復元できる |
| F-11 | キーワード検索 | 管理番号・機器名・メーカー・型番・シリアル番号を検索できる |
| F-12 | 条件絞り込み | 種別・状態・場所・利用者で絞り込める |
| F-13 | CSV出力 | 管理担当者が検索・絞り込み結果をCSV出力できる |
| F-14 | 無効な社員の割当確認 | 管理担当者が、無効なアカウントに残っている機器の割当を一覧で確認できる |

### 6.1 検索・絞り込み【確定・整理】

- キーワード検索と条件絞り込みを組み合わせて利用する。
- 利用者の絞り込みは、特定の社員・共有・未割当に対応する。
- 場所や状態の異なる機器を検索結果から区別できる。
- 削除済み機器を通常検索の対象にしない。
- 無効な社員に残っている割当を確認できる。

複数項目を指定した場合は条件をANDで組み合わせ、キーワードは対象項目のいずれかに一致するものを返す方針を提案する。検索・絞り込みは検索ボタンで実行する【確定】。部分一致・完全一致、空白・大文字小文字の扱い、並び順、ページネーションは設計案として画面設計書で管理する。

### 6.2 CSV出力【確定・整理】

- 出力できるのは管理担当者のみ。
- 現在指定している検索・絞り込み条件を反映する。
- 条件に一致する全件を対象とし、ページ分割を実装する場合も表示ページだけに限定しない。
- 現在の機器情報を出力し、削除済み機器と変更履歴は含めない。
- 管理番号などを含め、現物と照合できる一覧にする。

出力項目は次の14項目とする【確定】：管理番号、機器名、種別、場所、所在補足、利用者区分、割当社員、状態、メーカー、型番、シリアル番号、備考、登録日時、更新日時。上記の列順、UTF-8 BOM付き、日時は日本時間のYYYY/MM/DD HH:mm:ssを初期案とする。未登録の任意値は空欄とする初期案。内部ID・ハッシュ値・ログイン状態の版数は出力しない。CSV取り込みは初期版に含めない。

CSVは現在の機器情報を確認するための出力であり、履歴・アカウント・採番管理を含むDBバックアップの代わりにはしない。特殊文字と表計算ソフトの数式解釈への対策は実装時に具体化する。

### 6.3 履歴保存【整理】

- 同じ値のまま保存した項目には変更履歴を作らない。
- 1回の更新で複数の対象項目を変えた場合、変更を漏らさず記録する。
- 機器の更新と履歴保存を一体で成功・失敗させる。
- 機器を論理削除しても、既存の履歴は失わない。

過去の場所名・社員名は変更当時の名称を表示する【確定】。種別変更で管理番号も変わる場合は両項目を記録する【整理】。初回登録は変更履歴に含めず、登録日時を保存する【確定】。履歴の具体的な表示形式はDB設計書の初期案として管理する。

## 7. アカウント・パスワード運用

### 7.1 アカウント作成【確定】

管理担当者がアカウントを作成する。社員による自己登録・承認待ちの機能は初期版に含めない。

### 7.2 無効化【確定・整理】

- 割当機器が残っていても無効化できる。
- 無効化しても既存の割当と過去の変更履歴を保持する。
- 無効な社員への新規割当は禁止する。
- 編集・復元時に、既存の無効な社員への割当を変更せず保持できる。
- 最後の有効な管理担当者は無効化できない。
- 残っている割当は管理担当者が一覧で確認し、返却・再割当を行う。
- 無効化されたアカウントはログインできない。
- ログイン済みであっても、無効化後のアクセスをサーバー側で拒否する。

無効化は機器の返却や割当解除を自動で行う操作ではない。実際の所在が未確認の機器を、無効化だけで「未割当」に変更しない。

再有効化は初期版に含める【確定】。管理担当者による氏名編集のみを許可し、既存ログインID・権限は変更しない【確定】。現在の氏名変更では、過去の履歴内の氏名を書き換えない。社員情報の物理削除は初期版では行わない方針を提案する。

### 7.3 パスワード【確定・整理】

- 管理担当者が初期パスワードを設定する。
- 初回ログイン時に本人による変更を必須にする。
- 忘れた場合は管理担当者がリセットし、その後のログインでも変更を必須にする。
- 変更が必要な状態では、機器・管理機能の利用を許可しない。
- 本人が通常時にも自分のパスワードを変更できる。
- 初期版ではメールによる自動リセットを実装しない。

パスワードは15〜64文字とし、英大文字・数字・記号などの組み合わせを強制しない【確定】。初期・リセット用も同じ長さのルールを適用する。リセットでは対象社員の既存ログインをすべて無効にし、再ログイン後に本人の変更を必須にする【確定】。30分間操作がなければ自動ログアウトし、操作を続けている間は保持時間を延長する【確定】。入力画面で文字を打っているだけの時間をどう扱うかは実装案で明記する。

パスワードのハッシュ方式・許可文字の詳細・初期値の受け渡し方法は実装時に具体化する。最後の有効な管理担当者の無効化を禁止する【確定】。最初の管理担当者をセットアップ時に作成すること、権限変更を追加する場合に最後の有効な管理担当者の降格も防ぐことは初期案とする。

## 8. 画面構成【機能要件からの提案】

| 画面 | 主な内容 | 利用者 |
|---|---|---|
| ログイン | 認証 | 両方 |

### 8.1 端末対応【確定】

- PCで全機能を利用することを前提とする。
- スマートフォンでは機器一覧・詳細を閲覧できるようにする。
- スマートフォンでの登録・更新・管理画面の操作性は初期版の保証対象にしない。
- スマートフォンで閲覧するために必要なログイン・必須パスワード変更も、小さな画面で操作できるようにする【整理】。

## 9. 主な利用フロー【整理】

### 9.1 導入

1. 初期管理担当者を用意する。
2. 管理担当者が社員アカウントと場所を登録する。
3. 機器を登録する。
4. 社員は初回ログインでパスワードを変更する。

初期管理担当者の作成方法は詳細設計で決める。

### 9.2 所在・利用者の確認

1. 社員がログインする。
2. 機器名・管理番号などで検索するか、場所・利用者などで絞り込む。
3. 一覧・詳細で現在の所在・利用者・状態を確認する。

### 9.3 移動・再割当

1. 管理担当者が対象の機器を開く。
2. 実際の移動・返却・再割当に合わせて情報を変更する。
3. 変更を保存し、履歴を記録する。

貸出申請・承認・予約のワークフローは設けない。

### 9.4 退職・利用停止

1. 管理担当者がアカウントを無効化する。
2. その社員に残っている割当を確認する。
3. 現物の返却・移動を確認して、場所・利用者・状態を更新する。

### 9.5 廃棄・誤登録

- 廃棄した機器：状態を「廃棄」に更新して記録を保持する。
- 誤登録した機器：論理削除し、必要に応じて復元する。
