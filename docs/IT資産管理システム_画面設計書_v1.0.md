## 1. 画面設計で確定した事項

| ID | 決定内容 |
|---|---|
| D-01 | 管理担当者の変更履歴を、機器詳細の下部に表示する |
| D-02 | PCのメニューは左側のサイドメニューにする |
| D-03 | 検索・絞り込みは「検索」ボタンで実行する |
| D-04 | スマートフォンの機器一覧は、機器ごとのカードで表示する |
| D-05 | 機器の登録・編集は、1画面にまとめて見出しで区切る |
| D-06 | 機器の登録・編集を保存した後は、機器一覧へ戻る |
| D-07 | ログインには専用のログインIDを使用する |
| D-08 | 機器が残っている場所も利用停止できる。既存の場所情報を保持し、新規選択は禁止する |
| D-09 | 初期版に場所の利用再開・アカウントの再有効化を含める |
| D-10 | 明るい背景と青いアクセントで統一する |

本書v1.2は要件定義書の本文v1.2・DB設計書v1.1と整合させている。既存ファイル名は継続使用し、版数は各文書の表で管理する。DBの物理名・文字数などの初期案を、ユーザー確定事項へ変更しない。

DB設計で確定した画面への影響：種別変更時は管理番号を再発行し、履歴は場所・利用者・状態・種別・管理番号の5項目を表示する。場所名・社員名は当時の名称を表示する。使用中は個人利用・共有、廃棄は未割当とする。ログインIDは大小文字を区別しない。最後の有効な管理担当者の無効化は禁止する。

### 1.1 細部確定の追加回答

| DT-05 | 廃棄の訂正 | 廃棄から他の状態へ戻せる。状態と利用者区分の整合ルールを適用し、変更履歴を保存する |

## 2. 共通方針

### 2.1 主な作業

- 一般利用者：社内すべての機器の現在の所在・利用者・状態を確認する。
- 管理担当者：上記に加え、機器情報の更新・履歴確認・CSV出力・場所とアカウントの管理を行う。
- ログイン後の通常の起点は「機器一覧」とする【設計案】。
- ダッシュボード、グラフ、通知、画像、QRコードの画面は追加しない【設計案】。

### 2.2 共通レイアウト【確定・設計案】

| 領域 | 配置・内容 |
|---|---|
| PCの左メニュー | アプリ名、機器一覧、削除済み機器、場所管理、アカウント管理 |
| ユーザー領域 | ログイン中の氏名・役割、自分のパスワード変更、ログアウト |
| メイン領域の上部 | パンくず、画面名、主な操作 |
| メイン領域の本文 | 検索、表・カード、詳細、フォームなど |
| 処理結果 | 本文上部のメッセージ領域 |
| 入力エラー | 該当項目の直下。必要に応じてフォーム上部に要約 |

一般利用者には「機器一覧」と本人のパスワード変更・ログアウトのみを表示する。ログイン・パスワード変更必須状態では、機器・管理メニューを表示しない。

PCは左メニュー幅224px、本文余白24pxを初期案とする。狭い画面では開閉式メニューに切り替える。フォームは文書全体の縦スクロールで全項目に到達できるようにし、固定高さで切り取らない。

### 2.3 表記【設計案】

- 画面とメッセージは日本語で統一する。
- 入力項目には「（必須）」「（任意）」を統一して付ける。
- 未入力の任意項目は「未登録」と表示する。
- 利用者は「社員名」「共有」「未割当」を明確に区別する。
- 無効な社員には「無効」、停止した場所には「利用停止」を文字で添える。
- 日時は日本国内の社内利用を想定した初期案として「YYYY/MM/DD HH:mm（日本時間）」を採用する。保存方式と正式タイムゾーンはDB設計時に確認する。
- 状態は色と文字で示し、色だけで区別しない。
- 管理番号はPC-000001・NET-000001の形式とし、種別ごとに独立した連番を使用する【確定】。

### 2.4 操作の統一【設計案】

- 登録の主ボタン：「登録する」。
- 編集の主ボタン：「変更を保存」。
- パスワード：「パスワードを変更」または「リセットする」。
- 削除：「削除する」、復元：「復元する」。
- 利用停止：「利用停止にする」、再開：「利用再開する」。
- 無効化：「無効化する」、再有効化：「再有効化する」。
- 安全な戻り操作：「キャンセル」「一覧へ戻る」。
- 通常の登録・編集の保存に、確認ダイアログを毎回追加しない。
- 削除・復元・利用停止・再開・無効化・再有効化・他者のパスワードリセットでは、対象と結果を確認できるようにする。
- 入力途中の変更を失う移動には確認を設ける。パスワードをブラウザーの永続ストレージに保存しない。

## 4. 画面遷移

### 4.1 認証から機器の確認まで

~~~mermaid
flowchart TD
    L["S-01 ログイン"] --> P{"パスワード変更が必要"}
    P -->|必要| W["S-02 パスワード変更"]
    P -->|不要| A["S-03 機器一覧"]
    W -->|変更成功| A
    A -->|詳細を見る| D["S-04 機器詳細"]
    D -->|検索条件を保持して戻る| A
    A -->|ログアウト| L
    D -->|ログアウト| L
~~~

未ログインのアクセスはS-01へ、変更必須のアクセスはS-02へ誘導する。無効なアカウントには機器画面を表示しない。30分間操作がなければログアウトする【確定】。操作中の保持時間延長・入力だけの時間の判定は実装時に具体化し、未保存入力を勝手に送信しない。

### 4.2 管理担当者の機器操作

~~~mermaid
flowchart TD
    A["S-03 機器一覧"] -->|新規登録| N["S-05 機器登録"]
    N -->|保存成功| A
    A -->|詳細を見る| D["S-04 機器詳細"]
    D -->|編集| U["S-06 機器編集"]
    U -->|保存成功| A
    D -->|削除を確認して実行| A
    R["S-07 削除済み機器一覧"] -->|内容を確認| D
    R -->|復元成功| R
    D -->|削除済みの確認を終える| R
~~~

取消時は原則として遷移元へ戻り、保存成功後の機器登録・編集はD-06によりS-03へ戻る。削除済みの詳細では通常編集を表示せず、復元操作を用意する。復元では既存の停止場所・無効な社員への割当を保持できる。競合時の表示などは第17章に従って具体化する。

## 5. S-01 ログイン

### 5.1 配置

左メニューのない中央のフォーム。アプリ名、見出し、入力欄、ログインボタン、エラーの順に配置する。

### 5.2 項目と操作

| 項目・操作 | 内容 |
|---|---|
| ログインID（必須） | 専用ID。メールアドレス入力を要求しない |
| パスワード（必須） | 初期状態は伏せ字。表示／非表示を切り替えられる |
| ログイン | 入力値を検証して認証 |
| 補足 | パスワードを忘れた場合は管理担当者への連絡を案内 |

自己登録・メールリセットのリンクは設けない。ログインID・パスワード・有効状態のどれが原因かを区別して外部へ明かさないエラーを初期案とする。

### 5.3 結果

| 状態 | 表示・動作 |
|---|---|
| 必須未入力 | 該当欄に「ログインIDを入力してください」など |
| 認証失敗 | 「ログインできません。入力内容を確認してください。利用停止については管理担当者へお問い合わせください」 |
| 変更必須 | S-02へ移動 |
| 通常成功 | S-03へ移動 |
| 通信・処理失敗 | 再試行できる案内。パスワードは返却・永続保存しない |

## 6. S-02 自分のパスワード変更

| 項目・操作 | 内容 |
|---|---|
| 現在のパスワード（必須） | 本人確認用。初回は初期値、リセット後はリセット値 |
| 新しいパスワード（必須） | 伏せ字、表示切り替え可能 |
| 新しいパスワードの確認（必須） | 一致確認 |
| パスワードを変更 | 保存成功後はS-03へ |
| キャンセル／ログアウト | 通常変更は遷移元へ。変更必須時は機器画面へ戻る操作を表示せずログアウトを用意 |

「初回ログインのため、パスワードを変更してください」など理由を表示する。入力不一致は「新しいパスワードと確認用の入力が一致しません」と表示する。

新しいパスワードは15〜64文字。文字種の組み合わせを強制しない【確定】。初期・リセット用にも同じ長さを適用する。現在のパスワードによる本人確認、許可文字の詳細・弱い値の拒否・再使用ルールは実装時の具体案として定義する。

## 7. S-03 機器一覧

### 7.1 PCの上からの配置

1. 見出し「機器一覧」。
2. 管理担当者のみ「機器を登録」「検索結果をCSV出力」。
3. 検索・絞り込みフォーム。
4. 件数・適用中条件・処理結果。
5. 機器一覧表。
6. ページ移動。

### 7.2 検索条件【確定・設計案】

| 項目 | 内容 |
|---|---|
| キーワード | 管理番号・機器名・メーカー・型番・シリアル番号を対象 |
| 種別 | すべて／PC／ネットワーク機器 |
| 状態 | すべて／使用中／保管中／故障／廃棄 |
| 場所 | すべて／登録済みの場所。停止した場所も既存情報の検索対象に含める |
| 利用者 | すべて／共有／未割当／社員。無効な社員も既存割当の検索対象に含める |
| 無効な社員への割当のみ | 管理担当者のみの追加条件 |
| 検索 | 入力した条件をまとめて適用 |
| 条件をリセット | 入力と適用中の条件を解除し、1ページ目を表示 |
| キーワードを消去 | 入力欄だけを消去。検索結果への反映は「検索」で行う |

場所・利用者の検索は、機器登録時の選択肢と区別する。利用停止・無効化を理由に既存機器が検索不能にならないようにする。

条件間はAND、キーワード対象項目間はOR、キーワードは部分一致を初期案とする。氏名の表記や正規化ルールはDB設計と合わせて決める。

### 7.3 表示列【設計案】

| 列 | 内容 |
|---|---|
| 管理番号 | 全番号。長い場合も全文確認できる |
| 機器名 | 機器を識別できる名称 |
| 種別 | PC／ネットワーク機器 |
| 場所 | 場所名、停止時は「利用停止」を併記 |
| 利用者 | 社員名／共有／未割当。社員が無効なら「無効」を併記 |
| 状態 | 文字付きの状態表示 |
| 詳細 | 「詳細を見る」リンク |

メーカー・型番などはS-04で確認する。一覧に全項目を詰め込まない。行全体のクリックに頼らず、明示的な詳細リンクを用意する。

### 7.4 件数・ページ移動【設計案】

- 20件／ページを固定の初期案とする。
- 初期順序は登録日時の新しい順、同じ日時は内部IDの降順。
- 「全53件中 1〜20件」など現在の範囲を表示する。
- 前へ／ページ番号／次へを表示し、境界では利用不可にする。
- 新しい検索では1ページ目へ。削除で現在ページが存在しなくなった場合は最後の有効ページへ。
- 確定した検索条件とページをURLで保持し、一覧・詳細・編集間で復帰できる。
- 並べ替え・表示件数切り替え・一括選択は初期版の追加案に含めない。

### 7.5 CSV

「検索結果をCSV出力」は最後に適用済みの条件を使用する。未実行の入力条件とは区別する。条件に一致する全件を出力し、表示中の20件に限定しない。削除済み機器・履歴は含めない。

出力項目は管理番号、機器名、種別、場所、所在補足、利用者区分、割当社員、状態、メーカー、型番、シリアル番号、備考、登録日時、更新日時の14項目【確定】。提示順の列、UTF-8 BOM付き、日本時間の秒までの日時表記を初期案とする。内部ID・ハッシュ値などは出力しない。件数0では利用不可と理由を示す。CSVをバックアップと呼ばない。

### 7.6 スマートフォン【確定・設計案】

表をカードに切り替える。各カードに管理番号・機器名・種別・場所・利用者・状態・詳細リンクを表示する。検索は「検索条件」を開く領域にまとめ、「検索」で適用する。

PC向けの登録・編集・CSV・管理画面を、スマートフォンの主な操作として表示しない案とする。これは表示上の整理であり、サーバーの権限は端末サイズではなく役割で判定する。

### 7.7 データ状態

| 状態 | 表示 |
|---|---|
| 機器未登録 | 「機器がまだ登録されていません」。管理担当者には登録への導線 |
| 検索結果なし | 「条件に一致する機器がありません」。条件リセット |
| 読み込み失敗 | 「一覧を読み込めませんでした」。再読み込み |
| 処理中 | 操作名と待機表示、二重実行防止 |
| 成功 | 「機器を登録しました」「変更を保存しました」など |

## 8. S-04 機器詳細

### 8.1 配置

| 順番 | 領域 | 内容 |

| 1 | 戻り導線・見出し | 一覧へ戻る、機器名、管理番号 |
| 2 | 状態・管理操作 | 状態。管理担当者のみ編集・削除 |
| 3 | 所在・利用状況 | 場所、所在補足、利用者区分、割当先、状態 |

| 5 | 補足 | 備考、登録日時、更新日時 |
| 6 | 変更履歴 | 管理担当者のみ、詳細の下部 |

### 8.2 変更履歴【確定・設計案】

| 列 | 表示内容 |
|---|---|
| 変更日時 | 日本時間の日時表示を初期案とする |
| 変更者 | 変更を実行した社員 |
| 変更項目 | 場所／利用者／状態／種別／管理番号 |
| 変更前 | 変更前の内容 |
| 変更後 | 変更後の内容 |

場所名・社員名は変更当時の名称を表示する【確定】。変更者も当時の表示値を用いるDB設計の初期案。利用者の履歴では区分と割当先を区別できる文章で表示する。例：「個人利用：山田太郎（yamada） → 共有」【表示形式の初期案】。種別変更で番号が変わった際は、種別と管理番号の両方を表示する。新しい順、10件／ページを初期案とする。初回登録は履歴を作らず、登録日時で確認する【確定】。履歴がない場合は「変更履歴はありません」。

一般利用者には、履歴・変更者・管理ボタンを返さない。CSSだけで隠す実装にしない。履歴閲覧のスマートフォン対応は初期版の保証対象外。

### 8.3 削除済みの表示

管理担当者がS-07から開いた場合、「削除済み」の注意と「復元する」「削除済み一覧へ戻る」を表示する。通常編集は表示しない。一般利用者には存在を確認できる詳細を返さずE-02相当を表示する。

## 9. S-05／S-06 機器登録・編集

### 9.1 共通配置【確定・設計案】

1画面を「基本情報」「所在・利用状況」「補足情報」の3見出しで分ける。ラベルを入力欄の上に置き、PCでは関連項目を2列、長文と条件付き項目は1列に配置する。入力欄の見た目・順序は登録と編集で共通化する。

### 9.2 入力項目

| グループ | 項目 | 入力形式 | 必須・任意 |
|---|---|---|---|
| 基本情報 | 機器名 | 1行テキスト | 必須 |
| 基本情報 | 種別 | PC／ネットワーク機器の選択 | 必須 |
| 基本情報 | メーカー | 1行テキスト | 任意 |
| 基本情報 | 型番 | 1行テキスト | 任意 |
| 基本情報 | シリアル番号 | 1行テキスト | 任意 |
| 所在・利用状況 | 場所 | 利用中の場所を選択 | 必須 |
| 所在・利用状況 | 所在補足 | 1行テキスト | 任意 |
| 所在・利用状況 | 利用者区分 | 個人利用／共有／未割当の選択 | 必須 |
| 所在・利用状況 | 割当先の社員 | 有効な社員を選択 | 個人利用の場合に必須 |
| 所在・利用状況 | 状態 | 4状態から選択 | 必須 |
| 補足情報 | 備考 | 複数行テキスト | 任意 |

ネイティブのselectを共通の選択UIとして採用する設計案。開いた選択肢の見た目はOS・ブラウザーに委ね、自前の高機能コンボボックスは追加しない。

### 9.3 条件付きの動作

- 初期値は未選択とし、意図せず個人利用・廃棄などを決めない。
- 「個人利用」の場合だけ割当先の社員を有効にし、必須とする。
- 「共有」「未割当」では割当先を使用しない。保存データにも割当先を残さない。
- 編集時の利用停止場所・無効な社員への既存割当は、現在値として表示する。
- 利用停止場所を他の機器へ新規選択すること、無効な社員へ新規割当することはできない。
- 既存の停止場所・無効な社員への割当を変更しない編集・復元では、既存値の保持を許可する【確定】。
- 使用中では個人利用・共有、廃棄では未割当とする【確定】。保管中・故障は3区分を許可する。整合しない場合は保存を拒否し、修正を案内する。状態変更だけで利用者や場所を自動変更しない。
- シリアル番号の重複を許可する【確定】。
- 廃棄状態からの訂正を許可する。変更後も状態・割当の整合ルールを適用し、履歴を保存する。
- 競合した保存は拒否する【確定】。入力中の非機密値を確認できる状態で「他の管理担当者が更新しました。最新情報を確認して再編集してください」と案内し、再読み込みで失われる入力を説明する【設計案】。強制上書き・自動マージは追加しない。
- 登録後も種別を変更できる。保存時に変更先の種別で管理番号を再発行し、内部機器IDを保持する【確定・整理】。種別の入力欄付近に「種別を変更すると管理番号が再発行されます」を示す【設計案】。

### 9.4 表示専用項目

登録では「管理番号は登録後に自動発行されます」。編集では現在の管理番号・登録日時・更新日時を表示し、入力欄として扱わない。種別変更時の新番号は保存成功時に確定し、一覧に表示する【設計案】。管理番号の直接編集は行わない。

### 9.5 保存・取消・失敗

| 操作・状態 | 結果 |
|---|---|
| 登録成功 | S-03へ移動。「機器を登録しました」 |
| 編集成功 | S-03へ移動。編集前の検索条件を保持し「変更を保存しました」 |
| 条件から外れた機器の編集 | 保存成功は通知する。一覧には検索条件に合う機器だけを表示する |
| キャンセル | 遷移元へ戻る。変更があれば破棄を確認 |
| 入力エラー | 同じ画面で非機密の入力値を保持し、該当欄に説明 |
| 保存失敗 | 同じ画面で再試行を案内。完了したような表示にしない |

入力エラーの例：「場所を選択してください」「個人利用の場合は割当先の社員を選択してください」。文字数・重複ルールはDB設計で確定し、画面とサーバーで一致させる。

## 10. S-07 削除済み機器一覧

- 管理担当者のみ利用できる。
- 削除済み機器を一覧表示し、内容・既存履歴の確認と復元へ進める。
- 列の初期案：管理番号、機器名、種別、場所、利用者、状態、内容確認、復元。
- 通常一覧とは別の表示であることを「削除済み機器」の見出し・案内で明示する。
- 20件／ページ、管理番号順を初期案とする。削除日時・削除者の記録は未確定なので、確定した列として追加しない。
- 復元成功後はこの一覧に留まり、「機器を復元しました」と表示する。
- 0件の場合は「削除済みの機器はありません」。
- 完全削除ボタンは設けない。

復元時に停止場所・無効社員が残る場合、既存値を保持した復元を許可する。勝手に変更・再有効化しない。確認には停止・無効の状態を表示する設計案とする。

## 11. S-08／S-09 場所管理

### 11.1 S-08 場所一覧

| 列・操作 | 内容 |
|---|---|
| 場所名 | 執務室・会議室・倉庫など |
| 利用状態 | 利用中／利用停止 |
| 登録機器数 | 論理削除されていない機器の件数 |
| 機器を見る | 場所を指定したS-03へ |
| 名称を編集 | S-09へ |
| 利用停止／利用再開 | C-01で確認して実行 |
| 場所を登録 | S-09へ |

停止した場所は一覧に残し、状態別に絞り込める案とする。停止確認には「この場所への新規選択を停止します。既存機器の場所は変わりません」と表示する。再開後は新規選択が可能になる。

### 11.2 S-09 場所登録・名称編集

| 項目・操作 | 内容 |
|---|---|
| 場所名（必須） | 1行テキスト |
| 登録する／変更を保存 | 成功後S-08へ |
| キャンセル | S-08へ、未保存変更を確認 |

新規登録時の状態は「利用中」とする設計案。利用停止・再開は一覧の明示操作で行い、名称編集と混在させない。

利用停止した場所も含め、場所名の重複を禁止する【確定】。既存の履歴は当時の場所名を保持する【確定】。場所名は前後の空白を除去して保存・比較し、英字の大小文字は区別する【確定】。場所の物理削除、住所・拠点階層・棚の専用項目は追加しない。

## 12. S-10／S-11 アカウント管理

### 12.1 S-10 アカウント一覧

| 列・操作 | 内容 |
|---|---|
| 氏名 | 社員名 |
| 氏名を編集 | S-11の氏名編集モードへ。管理担当者のみ |
| ログインID | 専用ID |
| 役割 | 管理担当者／一般利用者 |
| 利用状態 | 有効／無効 |
| 割当機器数 | 個人割当の機器数。論理削除済みは除く初期案 |
| 割当機器を見る | 社員条件を指定したS-03へ |
| 無効化／再有効化 | C-01へ |
| パスワードリセット | S-12へ |
| アカウントを登録 | S-11へ |

無効な社員も一覧に残し、有効・無効で絞り込む案とする。パスワード・ハッシュ値は一覧や通常詳細に表示しない。

割当機器が残っていても無効化できる。確認には残存件数と「機器の割当は保持されます」を表示する。再有効化は同じ社員・ID・役割・割当を保持し、ログインを再開できるようにする。

最後の有効な管理担当者の無効化は禁止する【確定】。画面には理由を表示し、サーバー側でも同時操作を含めて拒否する【整理】。

再有効化だけでパスワードや必須変更フラグを勝手に変更しない初期案とする。リセットを実行した場合は、既定どおり変更必須になる。

### 12.2 S-11 アカウント登録

| 項目 | 内容 |
|---|---|
| 氏名（必須） | 1行テキスト |
| ログインID（必須） | 半角英数字と . _ - のみ、空白禁止。大小文字を区別しない。重複禁止はDB設計の初期案 |
| 役割（必須） | 一般利用者／管理担当者。一般利用者を初期値とする案 |
| 初期パスワード（必須） | 伏せ字・表示切り替え |
| 初期パスワードの確認（必須） | 一致確認 |
| 登録する | 成功後S-10へ |
| キャンセル | S-10へ |

新規アカウントは有効・初回変更必須として作成する。管理担当者を選ぶ際は、機器更新・履歴・CSV・アカウント管理などの権限を持つことを説明する設計案。

パスワードを完了画面・メッセージ・URLへ再表示しない。受け渡し方法は実装前に決める。自己登録・部署・メールアドレスの項目は追加しない。

### 12.3 S-11 氏名編集モード【機能は確定・配置は設計案】

登録済みアカウントは氏名のみ編集できる。S-10からS-11の共通フォームを目的別に表示する初期案。新しい画面IDは増やさない。

- 見出し「氏名を編集」、対象ログインID・役割・有効状態は表示専用。
- 入力は「氏名（必須）」のみ。初期・現在パスワードは入力させない。
- 「変更を保存」でS-10へ戻り「氏名を変更しました」。取消はS-10へ戻る。
- 内部社員IDと機器割当は維持し、現在の表示名を更新する。過去の履歴名は書き換えない。
- 既存ログインID・権限の変更は、UI・サーバーの両方で許可しない。

最後の有効な管理担当者の無効化禁止は確定している。

## 13. S-12 他者のパスワードリセット

対象の氏名・ログインIDを表示専用にして、別の社員への操作ミスを防ぐ。

| 項目・操作 | 内容 |
|---|---|
| 新しい初期パスワード（必須） | 伏せ字・表示切り替え |
| 新しい初期パスワードの確認（必須） | 一致確認 |
| リセットする | C-01で対象・次回変更必須を確認して実行 |
| キャンセル | S-10へ |

成功後はS-10に戻り「パスワードをリセットしました。本人の次回ログイン時に変更が必要です」と表示する。秘密値は通知文に含めない。対象社員の既存ログインをすべて無効にする【確定】。確認にはその影響も表示する。次のアクセスでS-01へ誘導し、リセット後のパスワードで再ログインした後はS-02の必須変更へ進む。無効化はサーバー側で判定する。

## 14. C-01 共通確認

アプリ側の共通ダイアログとし、ブラウザーのalert・confirm・promptで代用しない。タイトル、対象、操作結果、取消、具体的な実行ボタンを表示する。

| 操作 | 主な確認内容 | 実行ボタン |
|---|---|---|
| 機器の削除 | 管理番号・機器名。通常一覧から除外し、後で復元可能 | 削除する |
| 機器の復元 | 対象。通常一覧へ戻す。場所・利用者は自動変更しない | 復元する |
| 場所の利用停止 | 対象・残存機器数。新規選択を禁止し既存情報は保持 | 利用停止にする |
| 場所の利用再開 | 対象。新規選択を再開 | 利用再開する |
| アカウント無効化 | 対象・割当件数。ログイン禁止、割当は保持 | 無効化する |
| アカウント再有効化 | 対象。現在の役割でログインを再開 | 再有効化する |
| 他者のパスワードリセット | 対象。新しい初期値に変更し次回変更必須 | リセットする |
| 未保存変更の破棄 | 未保存の入力が失われる | 保存しないで戻る |

キーボードで操作でき、表示時は取消側にフォーカスを置く。背景操作を止め、閉じたら起点へ戻す。失敗時は確認内容を保って再試行を案内し、成功前にダイアログを閉じない。

## 15. エラー・状態表示

## 17. 初期案・実装時の確認事項

利用ルールは第1.1節・要件定義書第16.1節で確定した。以下は具体的な設定・実装方式であり、個別の回答済み事項とは区別する。

| 分類 | 初期案・確認内容 |
|---|---|
| 一覧・履歴 | 一覧20件、履歴10件／ページ。部分一致・条件保持・並び順の初期案を実装で検証 |
| 入力長 | DB設計書の上限をUI・サーバーに共通適用。場所名の前後空白除去とID文字種は確定済み |
| 氏名編集 | S-11を目的別に使用する配置案。登録フォームの秘密値を編集モードへ流用しない |
| 停止・無効情報 | 既存値保持を許可。表示・確認文言、保存中の競合の案内を実装 |
| パスワード | 長さ・リセット時全ログイン無効化・無操作30分は確定。本人確認・受け渡し・許可文字の細部を具体化 |
| データ保護 | row_versionでの拒否・再編集案内、セッション切れ時の非機密入力の扱い |
| CSV | 14項目は確定。提示順、UTF-8 BOM付き、日時・数式解釈対策を初期案として具体化 |
